### 1.0.0 / 2026-10-20

The first release of the rewrite: prefixed, K-sortable ids a person can read, wire-compatible with the Elixir `uxid` package. It covers time-based generation, deterministic ids through `Options::from`, decoding with `is_valid` and `is_deterministic` and their `_with` forms, and the `Monotonic` generator. The default features are `std` and `getrandom`; `serde` is declared and derives nothing yet. With no feature the crate is `no_std` with `alloc`, and the caller supplies the byte source and the time. The runtime dependencies are `sha2`, always on with its default features off, and the optional `getrandom` and `serde`. The minimum supported Rust version is 1.85. It is checked against the conformance corpus vendored from riddler/uxid-ex at the tag `v2.10.0` (`conformance/SOURCE.json` records the tag, its commit and the corpus hash), and every case in it passes with no skip list. This release replaces the 2020 0.0.1 placeholder, which held no library: that placeholder is gone, and its entry below is kept as it was written.

**Added**

- `decode_with(id, delimiter, now)` reads an id back to a `Decoded` as uxid-ex's wire format defines it: the prefix (everything before the last delimiter found reading left to right, `None` with no delimiter), the size and time form the body length in bytes gives, whether the body is deterministic, and the time (`None` for a deterministic body; a compact time's high bits come from the clock `now`). The lengths 10 and 18 are always read as standard time. It needs no feature and builds under `no_std`, and it never panics on malformed input.
- `decode(id)`, behind the default `std` feature, is `decode_with` with the delimiter `_` and the system clock, which it reads only for a compact body.
- `Decoded`, read through `prefix()`, `size()`, `is_compact()`, `is_deterministic()` and `time()`; its fields are private.
- `is_valid(id)` and `is_deterministic(id)` answer whether a string decodes under `_`, and whether it decodes to a deterministic body. Neither reads a clock or needs a feature.
- `Error::Empty`, `Error::InvalidLength` and `Error::InvalidCharacter` (codes `empty`, `invalid_length` and `invalid_character`, the corpus names) refuse a malformed id, checked in that order; `Error::EmptyDelimiter` refuses an empty delimiter on decode too.
- `Options::from` asks for a deterministic id: the marker `z` (`Z` in upper case) followed by the first characters of a SHA-256 digest of the prefix, a zero byte, `from` as UTF-8, a zero byte and one byte holding the number of hash characters, at the size's standard body length, as uxid-ex's wire format defines it. `generate_with` and `generate` build it; with `from` the byte source is never called and the time, `now`, `compact_time` and `rand_size` are not read. It needs no feature and builds under `no_std`.
- `Error::RandWithFrom` (code `rand_with_from`, a corpus name) refuses fixed random bytes asked for with `from`.
- `generate_with(&Options, &mut impl ByteSource, now)` builds a time-based id as uxid-ex's wire format defines it, from the options prefix (an empty string is no prefix), size (`Size`, parsed from `xs`, `s`, `m`, `l`, `xl` and the long spellings), rand_size, compact_time, case, delimiter and time, taking random bytes from the byte source and the time from `now` when the options set none. It needs no feature and builds under `no_std`.
- `generate(&Options)`, behind the default `std` and `getrandom` features together, is `generate_with` with the platform's secure source and the system clock.
- `now_millis()`, behind the `std` feature, reads the system clock in milliseconds since the Unix epoch, for passing as `now` beside a byte source of your own.
- The `ByteSource` trait fills a byte slice and returns a `Result`; a `&mut` reference to a source and a `Box` of one are sources too. `GetrandomSource`, behind the `getrandom` feature, is the platform's secure source.
- `Options::rand` fixes the random field's bytes for reproducible test vectors only; it is never a source of randomness.
- `Error`, a `#[non_exhaustive]` enum whose `code()` is the refusal's stable name: `compact_time_out_of_range`, `rand_width_mismatch` and `rand_size_too_large` as the wire format names them, and this crate's `time_out_of_range`, `empty_delimiter`, `unknown_size` and `byte_source`. `Error` and `Options` are `Clone`, not `Copy`.
- `Monotonic`, a monotonic generator the caller holds: `Monotonic::new(&Options)` builds one for the options' prefix (an empty one is no prefix), size, random width, compact time, case and delimiter, and its `generate_with(&mut self, &mut impl ByteSource, now)` makes ids that increase strictly, also within one millisecond and when the clock moves back, as uxid-ex's wire format defines monotonic generation. It keeps the last time and the last random value in the value itself, never in a static or thread-local; within a millisecond it adds a step drawn uniformly from 1 to 2^(4w) (the low 4w bits of `ceil(w / 2)` bytes from the byte source, plus one, so there is no modulo bias), and when the field overflows it moves the time one millisecond forward with a fresh random value. A time set with `Options::time` is the time of every call. It needs no feature and builds under `no_std`. Use one generator per thread, or share one behind a lock of your own.
- `Monotonic::generate`, behind the default `std` and `getrandom` features together, is `generate_with` with the platform's secure source and the system clock.
- `Error::FromWithMonotonic` and `Error::RandWithMonotonic` (codes `from_with_monotonic` and `rand_with_monotonic`, the corpus names) refuse `Options::from` and fixed `Options::rand` bytes for a monotonic generator; `Error::EmptyRandWithMonotonic` (code `empty_rand_with_monotonic`, this crate's own) refuses a random width of 0 bytes, which leaves no field to step: an `xs` with `compact_time(false)`, or `rand_size(0)`. A monotonic `xs` uses compact time, and so a one-byte field, unless `compact_time` is called. A step that would carry the time past 2^48 - 1 is `Error::TimeOutOfRange`.
- `is_valid_with(id, delimiter, prefix)` answers whether an id decodes under `delimiter` and, given `Some(prefix)`, carries exactly that prefix (`None` or an empty prefix accepts any prefix or none); `is_deterministic_with(id, delimiter)` answers whether an id decodes under `delimiter` to a deterministic body. Both read no clock, need no feature, and answer `false` under an empty delimiter. `is_valid(id)` and `is_deterministic(id)` are these with the delimiter `_` and no required prefix.

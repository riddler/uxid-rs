### Added

- `Monotonic`, a monotonic generator the caller holds: `Monotonic::new(&Options)` builds one for the options' prefix (an empty one is no prefix), size, random width, compact time, case and delimiter, and its `generate_with(&mut self, &mut impl ByteSource, now)` makes ids that increase strictly, also within one millisecond and when the clock moves back, as uxid-ex's wire format defines monotonic generation. It keeps the last time and the last random value in the value itself, never in a static or thread-local; within a millisecond it adds a step drawn uniformly from 1 to 2^(4w) (the low 4w bits of `ceil(w / 2)` bytes from the byte source, plus one, so there is no modulo bias), and when the field overflows it moves the time one millisecond forward with a fresh random value. A time set with `Options::time` is the time of every call. It needs no feature and builds under `no_std`. Use one generator per thread, or share one behind a lock of your own.
- `Monotonic::generate`, behind the default `std` and `getrandom` features together, is `generate_with` with the platform's secure source and the system clock.
- `Error::FromWithMonotonic` and `Error::RandWithMonotonic` (codes `from_with_monotonic` and `rand_with_monotonic`, the corpus names) refuse `Options::from` and fixed `Options::rand` bytes for a monotonic generator; `Error::EmptyRandWithMonotonic` (code `empty_rand_with_monotonic`, this crate's own) refuses a random width of 0 bytes, which leaves no field to step: an `xs` with `compact_time(false)`, or `rand_size(0)`. A monotonic `xs` uses compact time, and so a one-byte field, unless `compact_time` is called. A step that would carry the time past 2^48 - 1 is `Error::TimeOutOfRange`.
